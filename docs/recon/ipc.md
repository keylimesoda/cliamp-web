  "report": "## 1. IPC protocol\n\n- **Transport:** newline-delimited JSON (NDJSON) over a local Unix-domain stream socket. IPC V2 only; every request requires `version: 2`. Maximum frame size is 1 MiB. A connection can carry repeated request/response frames; `subscribe` switches to server-to-client NDJSON events after its acknowledgement. Ordinary idle request reads time out after 60 seconds; subscriptions clear that read deadline.\n- **Socket path:** `<appdir>/cliamp.sock`, normally `~/.config/cliamp/cliamp.sock` (also follows the app config-dir resolution). If resolving the app directory fails, fallback is `<os-temp-dir>/cliamp.sock`. Server creates parent directory mode `0700`, socket mode `0600`, and `<socket>.pid` mode `0600`; it removes socket and PID file on close.\n- **Authentication:** no protocol token or challenge/credential field. Access is local filesystem access to the owner-only socket/directory. Server does not listen on TCP or expose a cross-device transport.\n- **Request envelope:** `{\"version\":2,\"id\":<JSON string|number|null>,\"method\":\"...\",\"operation\":\"...\",\"params\":{...},\"job_id\":\"...\",\"topics\":[...]}`. `version` is always emitted as 2 by the client marshaler; `id` is echoed without changing JSON type. Fields are method-dependent/optional except required version.\n- **Response envelope:** `{\"version\":2,\"id\":...,\"ok\":bool,\"result\":<raw JSON>,\"snapshot\":RuntimeSnapshot,\"job\":Job,\"error\":V2Error}`; optional payloads are omitted when unset. `V2Error={code,message,detail?}`. Stable error codes: `invalid_version`, `invalid_request`, `invalid_params`, `unknown_operation`, `not_found`, `conflict`, `unavailable`, `canceled`, `internal_error`.\n- **Direct methods:** `capabilities` returns available registered operation descriptions/parameter hints; `state.get` returns a runtime snapshot; `spectrum.get` returns visualizer bands; `operation.submit` accepts `operation` plus JSON `params` and immediately returns a job; `job.get` reads by `job_id`; `job.cancel` cancels by `job_id`; `subscribe` accepts an exact `topics` list, acknowledges, then streams events. `runtime.snapshot` and `runtime.status` operations alias `state.get`. Job states are `queued`, `running`, `succeeded`, `failed`, `canceled`; store capacity 256, terminal retention 15 minutes, jobs process-local and canceled on orderly shutdown.\n- **Runtime snapshot fields:** `revision`, `playlist_revision`, `state`, `track`, `logical_track`, `playback_detached`, `position`, `duration`, `seekable`, `volume`, `playlist`, `index`, `total`, `play_next_total`, `shuffle`, `repeat`, `mono`, `speed`, `eq_preset`, `eq_bands`, `device`, `visualizer`, `theme`, `stream_error`. Media control (MPRIS / NowPlaying)\n\n- **Shared source metadata:** `playback.Track` has title, artist, album, genre, track number, URL/path, artwork URL and duration. Model resolves live stream title overrides and supplies selected track path and current player duration.\n- **Linux MPRIS bus identity:** bus name `org.mpris.MediaPlayer2.cliamp`, object path `/org/mpris/MediaPlayer2`; session D-Bus required. MPRIS metadata map implementation exposes:\n  - always `mpris:trackid`: generated object path `/org/mpris/MediaPlayer2/Track/<sequence>`, sequence increments on track change;\n  - if non-empty: `xesam:title` (string), `xesam:artist` (one-element string array), `xesam:album` (string), `xesam:genre` (one-element string array), `xesam:url` (track path/URL string), `mpris:artUrl` (artwork URL string);\n  - if positive: `xesam:trackNumber` (integer), `mpris:length` (microseconds).\n- Linux `PlaybackStatus` is `Stopped`, `Playing`, or `Paused`; read-write `Volume` is linear 0.0–1.0 and converted to/from internal dB range −30 to +6. `Position` is read-only microseconds, refreshed on media state updates. `CanSeek` follows player seekability after updates (initialized true); `CanControl`, `CanPlay`, `CanPause`, `CanGoNext`, `CanGoPrevious` are true; `Rate`, `MinimumRate`, `MaximumRate` are 1.0. `HasTrackList=false`, `CanRaise=false`, `CanQuit=true`; supported URI scheme and MIME arrays are empty. No shuffle/repeat properties; no TrackList interface.\n- **Linux actions:** MPRIS `Play`, `Pause`, `PlayPause`, `Stop`, `Next`, `Previous`, relative `Seek` (offset in microseconds), `SetPosition` (absolute microseconds; ignored if supplied track object path is stale), and writable `Volume`. `Seeked` signal carries absolute position in microseconds after model seek completion.\n- **Position cadence:** model sends media state at attach and playback/state transitions; while playback is active it also sends a periodic update about once per second (network sampling accumulates to one second; notification occurs when sampled and player remains playing). Linux writes `Position` on every `Service.Update`. Model UI ticks are ordinarily 50 ms while playing, 16 ms for 60-FPS/raw-sample visualizer modes, or 500 ms in low-power mode; these tick intervals do not make media position publication faster than the approximately 1-second periodic notifier. Additional user/state transitions can publish sooner.\n- **macOS NowPlaying:** `MPNowPlayingInfoCenter` publishes `MPMediaItemPropertyTitle`, `MPMediaItemPropertyArtist`, `MPMediaItemPropertyAlbumTitle`, artwork (`MPMediaItemPropertyArtwork` when a local file artwork URL loads), `MPMediaItemPropertyPlaybackDuration` in seconds when positive, `MPNowPlayingInfoPropertyElapsedPlaybackTime` in seconds when nonnegative, and `MPNowPlayingInfoPropertyPlaybackRate` (1.0 playing, 0.0 paused). Playback state stopped clears info; playing/paused state is set separately. Remote actions: toggle play/pause, play, pause, next, previous, stop, change playback position in seconds (position-change command enabled only if seekable). No volume remote command.\n- **Windows:** no published metadata or position; global Play/Pause, Next, Previous and Stop hotkeys only. Other platforms use no-op stub.\n\n## 4. Runtime wiring (10 lines)\n\n1. `run(overrides, positional, daemon, visualizer60FPS)` loads `config.Load()` and applies command-line overrides; initializes file logging.\n2. Creates always-on cliamp radio channels, Radio, Local (if app directory available), and Podcast providers.\n3. Adds configured account providers conditionally; YouTube variants require configured/fallback OAuth or cookies and available `yt-dlp`.\n4. Resolves positional inputs/URLs, chooses startup/default provider behavior, loads resume state and builds the playlist.\n5. Constructs `player.Player` from sample rate, buffer, resample quality and bit depth; registers provider stream/source resolvers and stream metadata resolver.\n6. Applies player/playlist configuration and UI padding; if `--daemon`, dispatches into `runDaemon(player, playlist, ...)` and returns without creating a Bubbletea UI.\n7. TUI mode loads themes and Lua plugins, constructs `model.New(player, playlist, providers, defaultProvider, ...)`, then applies startup view/resume settings.\n8. Creates Bubbletea `Program`; wires OAuth URL callbacks and platform media service via `mediactl.New(prog.Send)`, then attaches service as model playback notifier.\n9. Starts `ipc.NewServerWithBroker(DefaultSocketPath(), pluginBroker)`, configures V2 dispatcher and registered operations, and publishes job events.\n10. Runs `mediactl.Run(program, service)`; on exit saves theme and captured resume position/context. Resume JSON is `<appdir>/resume.json`, atomically written mode `0600`.\n\n## 6. No-web-equivalent features\n\n- **Self-update:** `cliamp upgrade [--prerelease]` invokes the native upgrade flow to replace the installed binary with latest stable or prerelease.\n- **SSH streaming:** playlists can be created with `playlist create --ssh HOST`; tracks use `ssh://host/absolute/path`, and the native player runs system `ssh` to pipe remote file bytes into its decoder without mount/temp audio files.\n- **URL scheme:** `protocol register|unregister|status` manages desktop registration of `cliamp://`; `open` validates link actions and routes URL, provider album/playlist, or provider top-search-match play/queue actions into local IPC (albums/playlists are play-only; URL targets are HTTP(S)).\n- **Daemon:** root `--daemon` starts a headless player/control loop with local IPC, playback and provider/library APIs, queue/jobs/events and media controls; it has no TUI, Lua plugin loading, or theme/visualizer selection."
