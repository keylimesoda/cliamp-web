DSP/processing beyond EQ\n\n- **No player-side limiter, loudness normalizer, or ReplayGain stage** is present. The −2 dB attenuation below is a fixed resampling headroom adjustment, not dynamic limiting/normalization.\n- **Rate conversion:** when source and output sample rates differ, input samples are multiplied by `0.7943282347242815` (10^(−2/20), −2 dB) before the `beep.Resample` sinc converter. If rates match, the source is passed through without attenuation or resampler. Quality factor comes from `resample_quality` (1–4). This fixed headroom protects against interpolation overshoot; code comments document a square-wave resampler peak around 1.20 reduced to about 0.95.\n- **Playback speed without pitch change:** WSOLA time-stretching for ratios other than 1.0; player setter clamps to **0.25×–2.0×**. At 1.0× it passes through. Per frame: sequence/output advance `3584` samples (~81 ms at 44.1 kHz), overlap `512` samples (~12 ms), source window `4096` samples, search range ±`1024` samples (~23 ms), coarse correlation stride `8`, and `8` candidate offsets retained for refinement. Crossfade is linear (`alpha[i] = i/512`) over the overlap; offset selection uses normalized cross-correlation. The sequence/overlap duration scales with the active sample rate.\n- **Volume:** dB gain converted as `10^(dB/20)` and applied after the visualization tap; range is current floor through +6 dB. Floor is clamped to −90..0 dB, defaults to −50 dB, and raising the floor raises current volume if needed.\n- **Mono:** optional L/R average `(L+R)/2`, duplicated to both output channels.\n- **Live network jitter handling:** ICY/unknown-length responses are decoded off the speaker callback into a circular decoded-audio buffer with **4 s capacity**. It starts in buffering state and resumes after at least **500 ms** buffered; underruns output silence and wait for that refill. Resume-from-silence and underrun-to-silence transitions use at most **64 samples** linear fades.\n- **Gapless track changes do not crossfade.** The source sequencer fills the remainder of the current audio block from the next track, giving a zero-gap boundary when it is available.\n\n## 3. Gapless playback\n\n- `gaplessStreamer` is always running in the speaker chain. On current-stream exhaustion, if `SetNext` has installed a preloaded stream, it promotes that stream and fills the remainder of the same sample block from it. Without a next stream it marks the player drained and fills silence; it does not stop the speaker stream.\n- The model chooses the upcoming playlist/queue item (or current logical item when detached). It does not arm a next track when the current track is live, when there is no next item, or when the next yt-dlp path is the same as the current path. A preload failure suppresses retries for that path until another track starts. Queue/order mutations clear and rearm stale preloads.\n- **Local/non-stream next tracks:** preload is attempted as soon as a target exists.\n- **`Stream` next tracks:** only preloaded when current playback has a positive duration and remaining time is at most **3 seconds**. With unknown duration, no stream preload is armed.\n- **yt-dlp next tracks:** when current duration is known, defer preload until at most **15 seconds** remain; if current duration is unknown, the positive-duration deferral cannot apply and preload proceeds immediately.\n- Seek, stop, track replacement, and playlist/order changes invalidate a queued preload. Generation/token checks prevent an obsolete asynchronous swap from replacing manually selected playback.\n\n## 4. ICY/stream metadata\n\n- HTTP GET requests send `Icy-MetaData: 1` and a cliamp User-Agent. If response header `Icy-Metaint` parses to a positive integer and a metadata callback exists, an ICY reader is inserted before decoding.\n- The wire format is `metaInt` audio bytes, then a one-byte metadata-block length (block bytes = length × 16), then that many metadata bytes. The reader prevents decoder reads crossing metadata boundaries, strips the block, trims trailing NUL padding, and extracts `StreamTitle='…'` up to the closing quote-semicolon; it tolerates a closing quote without semicolon. Empty blocks/missing title do not clear the current title.\n- The callback atomically stores the non-empty title. Each new pipeline build clears player-side stream title; the UI clears its own title on track transition. UI polls `Player.StreamTitle()` during its model update tick and when a changed non-empty value appears, updates title state and scrolling. For display, stream titles containing `\" - \"` split once into artist/title if both are non-empty; otherwise the raw string is the title. Only `Stream` tracks use this override.\n- OGG/Vorbis HTTP uses a chained OGG reader. At each logical bitstream boundary it extracts case-insensitive Vorbis `ARTIST` and `TITLE` comments, emitting `Artist - Title` if both exist, otherwise title alone.\n- Optional API metadata resolution is separate from ICY: resolver provides fetch function and interval. On playback it fetches immediately, then on each interval; nonpositive interval defaults to **15 seconds**. Only non-empty successful results are applied; cancellation discards stale fetch results.\n\n## 5. Streaming and seeking\n\n- Normal stream path issues HTTP **GET**, requires status 200, sends User-Agent and `Icy-MetaData: 1`; it does not send an HTTP `Range` header. A live/direct read has a **10 s per-read stall timeout**. For `Content-Length < 0` (including chunked transfer) or any `icy-*` response header, network decoding is marked for background prefetch. A chunked response reports unknown total length (`-1`).\n- Seekable buffered HTTP path downloads the entire response progressively to a temporary file, reading in **32 KiB** chunks. Readers can consume bytes as they arrive; reads/seek wait for requested data and time out after **5 s without download progress**. It does not issue byte-range requests. Seeking repositions a local cursor and restarts FFmpeg against a fresh reader from byte offset zero with output-side `-ss` time offset.\n- Finite HTTP (`!live`, positive `Content-Length`) is routed through that buffer/FFmpeg path when FFmpeg exists: initial response is opened to inspect headers and closed, then a second GET begins the background download. Explicit buffered-URL matches and resolver-provided segment sequences also use this seekable buffer. Segment sources are fetched sequentially and concatenated; known content length is `-1`.\n- HTTP streams with unknown/chunked length and direct streaming codecs are non-seekable. Native file decoders for local files are seekable. Local FFmpeg formats seek by preparing a replacement FFmpeg process with `-ss` at the requested sample position; duration is probed with ffprobe. Custom streamer factories are marked seekable. HLS `.m3u8` is opened directly by FFmpeg and treated as non-seekable.\n- FFmpeg stdin-fed HTTP stream and chained live OGG decoders have no seek behavior. `Seek` on non-seekable sources returns nil without changing position. Engine `IsStreamSeek()` always returns false.\n- Relative seeks add requested duration to current decoder position; lower bound is zero, and a known decoded length clamps target to the last frame (`length−1`). Buffered/native seek clears any preloaded next track. For yt-dlp, seek restarts the yt-dlp→FFmpeg pipeline at integer target seconds; current stream is muted during rebuild, duration bounds the target to at most one second before end, and stale/cancelled generations are discarded.\n\n## 7. Resume\n\n- One global last-playback snapshot, not a history/map of positions per track. JSON file is `<app config dir>/resume.json` (Linux test path: `~/.config/cliamp/resume.json`), written atomically with mode `0600`.\n- JSON fields: `path` (required path/URL), `position_sec` (integer), optional `playlist`, optional `context` (playlist track list), optional `context_index`. `Load()` returns zero state when unreadable/malformed. Saves silently ignore errors; save is skipped for empty path, negative position, or zero position with no context.\n- Model resume hints match the exact track path. On startup the hint is used for restored Jellyfin context, Mixcloud URLs, or a positional track when not in default radio mode. A provider `TrackPosition` capability takes precedence over the local hint for remote/stream tracks.\n- Position is captured on quit only when a path is active, playback is running and not buffering, no gapless advance is pending, and track is not live. yt-dlp is excluded except Mixcloud; eligible non-live local/non-yt-dlp tracks include finite HTTP sources. Exit position is whole seconds and must be >0 to be persisted by main shutdown wiring.\n- Continuous checkpoints are wired when the default provider is Jellyfin; they only persist tracks recognized by Jellyfin `RestoreTrack`. The model records track/context at playback start and checkpoints decoder position at most every **2 seconds**, only while playing, not buffering, not seeking/previewing/in-flight/pending, and only when track context index is valid. Context index disambiguates duplicate paths and restores playlist source state. Resume callbacks also record the initial track position/context when a track starts.\n- Resume seeking waits until matching playback starts; it is skipped when saved seconds are ≤0 or player says source is not seekable. Target is clamped to duration. Mixcloud yt-dlp restore invokes seek-by-restart. Failed resume seeks retain/re-arm behavior as defined by playback startup path; a successful seek consumes the hint.\n\n## 8. Audio quality settings (`docs/audio-quality.md`)\n\n| TOML key | Documented choices/default | Effect |\n|---|---|---|\n| `sample_rate` | 22050, 44100, 48000, 96000, 192000 Hz; documented default 44100 | Output sample rate sent to audio device; docs note 48000 matches many DACs. Source is converted when it differs. |\n| `buffer_ms` | 50–5000 ms; default 250 | Speaker/device buffer; lower reduces latency, higher reduces glitches. Docs suggest 200 for pops and 2000 for unstable radio; larger setting can add up to two seconds playback latency. |\n| `resample_quality` | 1–4; default 4 | Sinc interpolation quality for mismatched source/output rates; 4 highest quality, 1 fastest. |\n| `bit_depth` | 16 or 32; default 16 | FFmpeg output precision. 16 is signed 16-bit PCM; 32 is float PCM and preserves up to 24-bit audio without truncation. Documentation lists m4a, aac, alac, opus, wma, webm as affected FFmpeg formats. Native mp3/flac/wav/ogg decoding is unaffected. |\n\nAll options are optional in the document and changes apply on next cliamp launch. Its recipe values: high-resolution uses 96 kHz, 250 ms, quality 4, 32-bit; low-latency uses 44.1 kHz, 200 ms, quality 1; unstable radio uses 2000 ms. `config.toml.example` separately documents `sample_rate = 0` as auto-detect (the quality doc’s stated default is 44100); config’s general defaults set buffer 250, resample quality 4, bit depth 16.\n\n## 9. Decoding and browser-native formats\n\n- **In-process native Go decoders:** `.mp3` (beep/mp3), `.wav` (beep/wav), `.flac` (beep/flac), `.ogg` (beep/vorbis). HTTP OGG/Vorbis has a dedicated in-process chained decoder to continue through logical bitstreams and read Vorbis comments. If native decode fails, local decode falls back to FFmpeg; HTTP fallback opens the URL directly with FFmpeg.\n- **FFmpeg required by extension:** `.m4a`, `.aac`, `.aacp`, `.m4b`, `.alac`, `.wma`, `.opus`, `.webm`. Local files stream through FFmpeg PCM output and support restart seeking. HTTP such formats are fed through the existing HTTP/ICY reader into FFmpeg stdin and do not support seek. HLS `.m3u8` is handled by FFmpeg opening the URL itself. A finite HTTP source with length and available FFmpeg uses buffered FFmpeg even when its codec would otherwise be native.\n- **OGG codec distinction:** `.ogg` first attempts in-process Vorbis. OggFLAC/OggOpus that fail Vorbis initialization fall back to FFmpeg. `.opus` extension directly requires FFmpeg in cliamp.\n- **yt-dlp URLs:** separate from extension routing; `yt-dlp` selects best direct HTTPS/HTTP audio (then non-m3u8 audio, then best fallback), writes downloaded media to stdout; FFmpeg reads the pipe and emits stereo PCM at configured rate and bit depth. Both executables are required. Seeking rebuilds the pipeline with FFmpeg `-ss`; yt-dlp itself is not a browser-native decode path.\n- **Browser-native equivalents for the requested PWA media set (modern Chromium media stack; exact support depends on codec/container):** MP3, AAC (commonly AAC in MP4/M4A; raw AAC/AAC+ stream support is not universal), FLAC, Opus, WAV/PCM, and OGG/Vorbis are browser-playable formats. This differs from cliamp routing: FLAC and OGG/Vorbis are in-process Go there; AAC and Opus extensions go through external FFmpeg there. WebM is also a browser media container, but cliamp routes `.webm` through FFmpeg."
