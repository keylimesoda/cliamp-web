Plugin API surface\n\n### Globals and registration\n- `plugin.register(opts) -> plugin_object`: opts fields are `name` (required by documented contract; installed filename remains the owner of trust and publish namespace), `type` (`\"hook\"` or `\"visualizer\"`), optional `version`, `description`, and `permissions` array. Runtime accepts type/name as strings and metadata fields are stored as strings; a non-array permissions value errors. Allowed permission strings are exactly `\"control\"`, `\"exec\"`, `\"keymap\"`; unknown values raise a Lua error.\n- Plugin object methods use colon syntax (self is implicit first Lua argument):\n  - `p:on(event, callback) -> no return`: subscribes a Lua function to an event; callback receives one table argument, including `{}` for empty event data.\n  - `p:config(key) -> string | nil`: reads `[plugins.<installed-plugin-name>]` config; only string values are returned. Missing key -> nil.\n  - `p:publish(topic, payload, options?) -> true | nil, error`: JSON-serializes payload and publishes topic `plugin.<installed-filename-sanitized>.<topic>`. `options.retain` truthiness requests in-memory retention. Nil/error if publisher unavailable, namespace collides, or serialization/publication fails. No permission needed.\n  - `p:bind(key, callback) -> true | false, reason`; or `p:bind(key, description, callback) -> true | false, reason`: requires `keymap`; key is lowercased and trimmed. Rejects missing permission, empty key, or core-reserved key. A nonempty description makes it visible in the Ctrl+K keymap overlay. Callback receives the normalized key string. `p:unbind(key) -> no return`: removes this plugin's binding for normalized key.\n  - `p:command(name, callback) -> no return`: registers/overwrites a named command; callback receives an array of argument strings and may return a string. Shell/IPC invocation is user initiated; no permission. Command deadline is 5 minutes.\n- `cliamp` is the only exposed host API namespace. Headers are stringified. Only `http` and `https`; 5-second client and dial timeout; response body reads capped at 1 MiB. Resolved non-public destinations are blocked: loopback, private, link-local unicast/multicast, multicast, unspecified. Guard applies on each dial, including redirect connections.\n\n### `cliamp.message`, `cliamp.notify`, `cliamp.log`\n- `cliamp.message(text:string, duration_secs?:number) -> no return`: output-only status-bar message. Cycles and nesting at/deeper than 64 levels convert to JSON null, not failure. Unsupported Lua value kinds become null.\n- `cliamp.crypto.md5(text:string) -> lowercase hex string`.\n- `cliamp.crypto.sha256(text:string) -> lowercase hex string`.\n- `cliamp.crypto.hmac_sha256(key:string, message:string) -> lowercase hex string`.\n\n### `cliamp.store`\nPer-plugin storage, no permission required:\n- `get(key:string) -> value | nil`.\n- `set(key:string,value:string|number|boolean|table) -> true | nil,error`.\n- `delete(key:string) -> true | nil,error`.\n- `keys() -> sorted array<string>`.\n- `clear() -> true | nil,error`.\nValues are converted via same Lua/JSON conversion; actual Lua source applies it to any Lua value accepted by `CheckAny` (nil becomes JSON null). Environment only `PATH`, `HOME`, `LANG`; process output combined stdout+stderr max 4 MiB; each line scan max 1 MiB; max 4 concurrent processes/plugin. Default hard timeout is 30 minutes; positive user timeout can reduce it but is clamped not to exceed 30 minutes. Processes stop on plugin unload/app exit. Exit callback codes: 0 success, actual nonzero process exit code, -1 cancel/timeout, -2 other wait/start failure. Without permission returns `nil,\"exec permission required\"`.\n\n## 2. Event hooks\nAll hooks subscribe with `p:on(event, callback)`. Asynchronous event handlers run in separate goroutines, serialized by each plugin VM mutex, with a 5-second callback context limit; shutdown `app.quit` dispatch is synchronous. Unknown event strings can be registered but are never emitted by core. Event field types are the Lua conversions of corresponding Go values (numbers, strings, booleans, nested tables/arrays).\n\n| Event | Callback payload | Trigger / cadence |\n|---|---|---|\n| `app.start` | `{}` | After plugins have loaded. |\n| `app.quit` | `{}` | Before shutdown, synchronously. |\n| `track.change` | `{title, artist, album, genre, year, path, duration, stream}` | Track successfully starts; initial playback and gapless transitions included; buffering, failed or superseded-before-start tracks excluded. |\n| `track.scrobble` | Same track keys plus `played_secs:number` | On track departure if elapsed is at least 50% of positive effective duration. Code uses player duration, falling back to track metadata duration; docs also describe “>=4 min,” but the inspected implementation condition is 50% only. |\n| `playback.state` | `{status, title, artist, album, genre, year, path, duration, stream, position}` | Emitted whenever `notifyPlugins()` is called (many state-changing paths and periodic playback ticks); status is `playing`, `paused`, or `stopped`; `title`/`artist` can reflect ICY stream-title override. The bundled plugin comment characterizes normal playback delivery as ~1 Hz; runtime trigger is the UI's dynamic tick/notify cadence, not a fixed event timer. |\n| `player.seek` | `{position:number, duration:number}` in seconds | Completed seek. |\n| `player.volume` | `{db:number}` | Once after a UI update detects volume differs from last emission. |\n| `player.eq` | `{bands:array<number> (10 dB values), preset:string}` | UI-update diff detects bands differ from last emission; implementation compares bands, so a preset-label-only change with unchanged gains does not fire. |\n| `player.mode` | `{shuffle:boolean, repeat:string}` | UI-update diff detects shuffle/repeat change. Repeat comes from playlist repeat string (`Off`/`All`/`One`). |\n| `queue.change` | `{count:number, index:number, queued:number}` | UI-update diff detects playlist length, current index or explicit queued-track count change. Key is named `queued`, value is queue length. |\n| `queue.end` | Track payload identical to `track.change` | Queue ends after an actually-started track: natural drain, gapless boundary with no queued next, next from last track, etc. Does not fire for manual stop, buffering, failed start, or empty playback. |\n| `playback.stop` | `{}` | Explicit user stop via key, IPC or media controls; queue exhaustion does not fire it. |\n\nThe state-diff events `player.mode`, `player.volume`, `player.eq`, `queue.change` run from a once-per-UI-`Update` comparison; the first update seeds prior values without emitting. `player.seek` and `queue.end` payloads are built at completion/end, not state-diffed. Event payload track metadata is exact keys above; `track.change` uses underlying track title/artist while `playback.state` resolves stream display overrides.\n\n## 3. Sandbox, loading, sources and manifest\n\n### Runtime and sandbox\n- Lua engine is GopherLua v1.1.2 (`github.com/yuin/gopher-lua`), documented and implemented as Lua 5.1 compatibility. Each plugin gets independent VM. VM opens standard libraries, then sandbox removes globals/functions.\n- Removed globals: `dofile`, `loadfile`, `load`, `loadstring`, `require`, `module`, `package`, `debug`, and entire `io` module.\n- `os` keeps safe time/date/clock/getenv functions; removes `execute`, `remove`, `rename`, `exit`, `setlocale`, `tmpname`.\n- `utf8` is replaced with a table exposing `utf8.char(...)`, added for Lua 5.1 compatibility; codepoints are integer arguments converted to runes.\n- Filesystem reads unrestricted by path; `fs.read` max 1 MiB. Writes/appends/removes/mkdir are limited to `/tmp`, `os.TempDir()`, resolved application config dir, `~/.local/share/cliamp`, `~/Music/cliamp`; real-path/symlink checks protect allowlist. No raw socket API. HTTP restricted to public destinations and 5-second timeout. `exec` is permission- and binary-allowlist-gated (details above).\n- No general CPU quota is configured. Event, timer and key callbacks call Lua with a 5-second context; command callback timeout is 5 minutes. Runtime plugin top-level `DoFile` has no explicit context timeout in `Manager.loadPlugin`; metadata scanning runs sandboxed with a 250 ms context. Visualizer documentation states a 10 ms render limit, while `Manager.RenderVis` invokes the shared 5-second `callBounded` context; no separate 10 ms enforcement was present in the inspected visualizer manager implementation.\n\n### Discovery/loading and approval\n- Default plugin directory is `~/.config/cliamp/plugins/` (resolved by appdir). Loader discovers direct `*.lua` files plus direct-child directories containing `init.lua`; directory name or filename stem is installed name. Sorted by installed name. Only entrypoint loads automatically; helpers cannot use `require` (removed).\n- Loader skips files not calling `plugin.register()`, disabled names from `[plugins].disabled` comma-separated setting, and per-plugin `[plugins.<name>].enabled = false`. It loads only plugins whose exact content hash is trusted. Edits invalidate trust.\n- Trust approvals stored in `plugins/.trust.json`; `cliamp plugins trust <name>` approves current content. Install prompts with content SHA-256, declared permissions and implicit access summary; install writes one `.lua` entrypoint with mode 0600 and records approval. Existing/manual files start untrusted.\n- Install/download client timeout 30 seconds, maximum Lua file size 1 MiB, empty response rejected.\n\n### Install source resolution\n- GitHub `user/repo` -> `https://raw.githubusercontent.com/user/repo/HEAD/<entrypoint>.lua`; `user/repo@ref` replaces HEAD with ref.\n- GitLab `gitlab:user/repo` -> `https://gitlab.com/user/repo/-/raw/HEAD/<entrypoint>.lua`; `@ref` replaces HEAD.\n- Codeberg `codeberg:user/repo` -> `https://codeberg.org/user/repo/raw/branch/main/<entrypoint>.lua`; `@tag` -> `https://codeberg.org/user/repo/raw/tag/<tag>/<entrypoint>.lua`.\n- Direct `http://`/`https://` URL downloads as-is; plugin name derives from URL path basename after stripping `.lua` (docs describe URL ending in `<name>.lua`).\n- Forge repository basename convention `cliamp-plugin-<name>` strips prefix; entrypoint `<name>.lua` at repository root. For repo names not carrying prefix, repo basename itself is short name/entrypoint.\n\n### Registration metadata (“manifest”)\nThere is no separate plugin descriptor file. Manifest is the Lua table passed to `plugin.register({...})`; fields consumed are `name`, `type`, `version`, `description`, `permissions`. Recognized `type` values documented: `hook`, `visualizer`. Recognized permission array values: `control`, `exec`, `keymap`. `name` determines metadata display, but immutable owner/trust identity and event namespace derive from installed filename/directory. Plugin-specific config is TOML `[plugins.<installed-name>]`; reserved top-level plugin config keys include `disabled` and `allowed_binaries`; per-plugin key `enabled` controls loading.\n\n## 4. Custom visualizers\n- Register with `plugin.register({name=..., type=\"visualizer\", ...})`.\n- Required method: `function p:render(bands, frame, rows, cols) -> string` (colon method receives plugin object first). Runtime invokes callback with args `(plugin_object, bands_table, frame_number, rows, cols)`. `bands` is a 1-indexed Lua table of exactly 10 numeric normalized spectrum levels (documentation says 0.0–1.0); `frame` is monotonically increasing frame counter; `rows`/`cols` available terminal dimensions. Returned text is terminal multi-line string and then fitted/clipped to configured dimensions.\n- Optional `function p:init(rows, cols) -> no return`; runtime calls `(plugin_object, rows, cols)` when selected. Optional `function p:destroy() -> no return`; runtime calls `(plugin_object)` when deselected.\n- Docs state render is called about 20 FPS during playback and a 10 ms limit; cadence is driven by dynamic UI visualizer tick interval. Render errors/non-string return reuse the previous successful frame (empty initially). Each selected visualizer is listed in registration order and integrated in built-in visualizer mode cycle.\n\n## 5. State persistence\n`cliamp.store` is an automatically persisted per-plugin key/value JSON file at `~/.local/share/cliamp/plugins/<installed-plugin-name>/store.json`. Store loads lazily on first access, remains in memory and writes after every set/delete/clear. Writes use temp file + rename, directory mode 0700, file mode 0600. Separate installed-name path prevents plugins from reading each other's keys. JSON-compatible strings/numbers/booleans/tables persist across restart; store does not target large data. `p:config(key)` is a separate read-only config.toml access path, not persistent plugin-owned write storage.\n\n## 6. Bundled plugins\n- `plugins/now-playing.lua` (`now-playing`, hook): on `track.change`, builds `artist - title` (title only if no artist), writes to `p:config(\"path\")` or `/tmp/cliamp-now-playing`, logs info, sends `cliamp.notify(title, artist)` or title-only notify. On `playback.state` status `stopped`, writes empty string; on `app.quit`, removes path. APIs: `plugin.register`, `p:config`, `p:on`, `cliamp.fs.write`, `cliamp.fs.remove`, `cliamp.log.info`, `cliamp.notify`.\n- `plugins/status-messages.lua` (`status-messages`, hook): app start displays “cliamp ready” for 2s; track change displays “Now playing: Artist — Title” for 3s (title-only if artist absent); playback state tracks prior status locally and displays Paused/Stopped for 1.5s only when status changes; track scrobble displays “Scrobble sent” for 2s. APIs: `plugin.register`, `p:on`, `cliamp.message`.\n- `plugins/webhook.lua` (`webhook`, hook): reads `url` config once during plugin startup. On track change, if set, POST JSON `{title,artist,album,genre,path}` to URL; logs warning for HTTP status >=400. APIs: `plugin.register`, `p:config`, `p:on`, `cliamp.http.post`, `cliamp.log.warn`.\n- `plugins/auto-eq.lua` (`auto-eq`, hook, version `1.0.0`, permission `control`): on track change lowercases genre, maps known exact genres to presets and then tries substring matching for compound genres; unmatched/empty -> `Flat`. Calls set preset and logs only if selected preset differs from previous track's preset. Genre mappings: Rock: rock, alt-rock, hard rock, metal, punk, grunge; Pop: pop, synth-pop; Jazz: jazz, smooth jazz, bossa; Classical: classical, orchestra; Electronic: electronic, edm, techno, house, trance, ambient; Hip-Hop: hip-hop, hip hop, rap, trap; R&B: r&b, rnb, soul; Acoustic: folk, acoustic, singer-songwriter, country; Podcast: podcast, speech; Late Night: lofi, lo-fi, chill. APIs: `plugin.register`, `p:on`, `cliamp.player.set_eq_preset`, `cliamp.log.info`.\n\n## 7. Lua version and host globals\nLua runtime is GopherLua v1.1.2 and Lua 5.1-compatible. Host globals explicitly installed: `plugin`, `cliamp`, `utf8` (compatibility helper). `prog.Send` is not exposed to plugin scripts; Go-side `ControlProvider` and `UIProvider` callbacks are wired internally to the UI update loop, with Go comments describing those as injected via `prog.Send`. Standard Lua globals/libraries are opened first, subject to sandbox removals above."
